# Phase 5: 課金・法務・Play 公開

Phase 4 までで機能は揃っている。ここから先は「売れる状態にする」ための作業で、
コードよりも Play Console と法務の比重が大きい。

現在の状態は **課金未実装・全機能開放** の先行版。
自分でインストールして使うぶんには完結しているが、配布はできない。

## 0. 最初にやること: 全機能開放を止める

[app/build.gradle.kts](../app/build.gradle.kts) の `PRE_RELEASE_UNLOCK` を `false` にする。

```kotlin
buildConfigField("boolean", "PRE_RELEASE_UNLOCK", "false")
```

このフラグが true の間、`LocalProGate` は誰に対しても Pro を返す。
**課金を実装しても、ここを false にしない限り有料機能は無料のまま出続ける。**
Phase 5 の作業はここから始める（そして、ここを最後に忘れない）。

false にすると Pro ツール17個が開かなくなるので、開発中は
デバッグビルド＋設定画面のトグル（`debugProOverride`）で確認する。

## 1. 署名鍵

現状、リリースビルドは **デバッグ鍵で署名されている**。
インストールはできるが、Play には出せない（Play はデバッグ鍵を弾く）。

本番鍵を作ってプロジェクト直下に `keystore.properties` を置く。
`.gitignore` 済みなので、コミットされる心配はない。

```properties
storeFile=upload.jks
storePassword=<パスワード>
keyAlias=upload
keyPassword=<パスワード>
```

ファイルがあれば自動でそちらが使われる（[app/build.gradle.kts](../app/build.gradle.kts) の `signingConfigs`）。

鍵は Play App Signing を使う前提でよい。その場合ここで作るのは
「アップロード鍵」で、紛失しても Google に再登録を申請できる。
配布用の署名鍵そのものは Google が持つ。

## 3. Play Billing

`core:billing` は `ProGate` インターフェースだけを外に見せる設計にしてある。
`LocalProGate` を `PlayBillingProGate` に差し替えれば、feature 側の変更は不要
（[core/billing/di/BillingModule.kt](../core/billing/src/main/kotlin/com/patoolbox/core/billing/di/BillingModule.kt) の `@Binds` を1行変えるだけ）。

### 商品構成

| 種類 | ID の例 | 備考 |
|---|---|---|
| サブスク（月額） | `pro_monthly` | |
| サブスク（年額） | `pro_yearly` | 月額の 10 か月分程度が相場 |
| 買い切り | `pro_lifetime` | 一度買えば永続。返金期間の扱いに注意 |

買い切りとサブスクを併売するので、**両方持っている場合の判定順**を決めておく。
`ProStatus.source` に `LIFETIME` / `SUBSCRIPTION` があるので、
買い切りを優先して表示する（利用者から見て「上位の権利」だから）。

### オフライン対応（これが要件の核心）

現場は圏外が多い。`ProStatus` に `OFFLINE_GRACE` を用意してあるのはこのため。

- 購入情報をローカルにキャッシュする（DataStore か Room）
- 起動時に再検証を試みる。成功したらキャッシュ更新
- 通信できない場合、猶予期間内ならキャッシュを信じて Pro を維持する
- 猶予期間は 7〜14 日程度。本番の直前に圏外で機能が死ぬのが最悪のケース

**この設計を省くと「電波が無いと有料機能が使えないアプリ」になる。**
PA の現場では致命的で、返金とレビュー低下に直結する。

### ライセンス許可リストの追加

`app/build.gradle.kts` の `licensee` ブロックに Play Billing 用の
`allowUrl`（Android SDK 利用規約）を足す必要がある。
足さないと `:app:licensee` がビルドを落とす（これは意図した動作）。

## 4. 法務

すべて日本語で用意する。アプリ内と Play ストア掲載の両方に必要。

### EULA（利用規約）

必ず入れる条項:

1. **商用利用の許諾** — 業務・有償の現場で使ってよいことを明記する。
   これは本アプリの売りなので、曖昧にしない
2. **計量法上の証明用途への不使用** — 「取引・証明」に用いる測定
   （騒音規制法の届出など）には使えないこと。検定を受けた騒音計を使うこと
3. **測定値に関する免責** — スマホ内蔵マイクの特性上、無校正では数dB〜十数dB
   ずれる。生じた損害について責任を負わない旨
4. **大音量出力に関する注意** — シグナルジェネレータとスイープ測定は
   PA から大音量が出る。機材・聴覚への影響について利用者の責任とする

3 と 4 は既にアプリ内（設定画面・各測定画面）に表示している。
EULA と表現を食い違わせないこと。

### プライバシーポリシー

- マイク音声は **端末内でのみ処理し、送信しない**（現在の実装はそのとおり）
- 測定記録・案件データは端末内 Room に保存、外部送信なし
- Phase 6 のクラウドバックアップを入れたらここを書き換える
- 課金情報は Google Play が扱い、アプリは購入トークンの検証結果のみ保持する

### 特定商取引法に基づく表記

有料販売なので必須。事業者名・所在地・連絡先・販売価格・支払時期・
解約方法（サブスクの場合）を記載する。個人事業なら氏名と住所の開示が要る。

### アプリ内 OSS ライセンス一覧

`:app:licensee` の出力（`app/build/reports/licensee/`）をそのまま使える。
設定画面から開けるようにする。

現在の依存はすべて Apache-2.0 / BSD-3-Clause。
GPL / AGPL / LGPL / 非商用限定は混ざっていない（[THIRD_PARTY.md](../THIRD_PARTY.md) 参照）。

### Data safety フォーム

- 音声を収集するが **端末外に送信しない**
- 記録は利用者が明示的に保存操作をしたときのみ作られる
- 削除手段がある（記録一覧から削除可能）

### ストア掲載情報

- スクリーンショット（Pro 機能が分かるもの。SPL / RTA / 残響測定あたり）
- 短い説明・詳しい説明
- アイコン（現在は暫定。文字バッジ方針との整合を取る）

## Phase 6（実装済み）

35ツールすべてが実装済み。以下は着手時に置いた前提で、
運用しながら見直す余地があるもの。

| ツール | 置いた前提 |
|---|---|
| 録音 | WAV 16bit / 48kHz。アプリ内部に保存し、WAV で個別に書き出す |
| スナップショット | 卓の内部データではなく **人が読める記録**。機種に依存しない |
| 機材台帳 | 同じ型番はまとめて数える（ケーブルを1本ずつ登録しない）。バーコードは未対応 |
| 見積・請求 | **端数処理は既定を切り捨て**。書類ごとに変更可。税率は 10% / 8%（軽減） |
| 稼働記録 | 日当と時間単価の両方。割増率は手入力。交通費は割増の対象外 |
| バックアップ | **自動のクラウド同期は入れていない**。ファイルに書き出して利用者が置く |

### 見直すかもしれない点

- **請求書番号の自動採番**: 現在は手入力。連番の付け方は事業者ごとに違うので、
  規則を決めてから自動化する
- **稼働記録から請求書を起こす**: 月の稼働をまとめて明細に流し込めると価値が出る。
  現在は別々
- **機材台帳のバーコード/QR**: 対応する規格を決めてから。カメラ権限が増える
- **バックアップの自動化**: 定期実行を入れるなら WorkManager。
  現在は利用者が任意のタイミングで書き出す

### ワイヤレス周波数調整: 混変調計算のみ実装済み

この道具は中身が2つに分かれる。

| | 内容 | 状態 |
|---|---|---|
| 法令上どの周波数を使えるか | 現行法＋TVホワイトスペース（運用地点ごとに違う） | **実装しない** |
| その組み合わせで混変調が起きるか | 純粋な計算 | 実装済み |

**割り当てデータベースは持たせていない。**
総務省の電波利用ポータル（`tele.soumu.go.jp`）は自動取得を 403 で拒否し、
`soumu.go.jp` 側の PDF はテキスト抽出に失敗する。検索で拾える資料は
2012〜2014年のもの（770-806MHz 時代＝2019年の移行前）が多く、
現行の割り当てを一次資料で確認できなかった。

記憶や二次情報で実装すると「アプリが使えると言ったから使った」で
違法運用になる。使用可能な周波数は機材の取扱説明書と免許の条件に従ってもらい、
アプリはその組み合わせの干渉だけを見る。画面にもその旨を常時出している。

将来 割り当てを載せるなら、**総務省の一次資料を人が読んで確認したうえで**、
出典と確認日をコードに残すこと。TVホワイトスペースは運用地点ごとに違うので、
全国一律の表を持たせることはできない。
